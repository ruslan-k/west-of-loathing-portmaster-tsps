# Кэш константных банков: замер реальной избыточности (census, default-off)

Роадмап-пункт «program/constant и vertex caches» требовал сначала измерить реальную избыточность и определить инвалидацию, а не включать кэш по догадке. Этот прогон — измерение.

## Прогон

- Сборка: `wol-horizon-build-uniform1`, ELF SHA-256 `abe18786588646374e608eac9dc02d3cb24af1816c67026fec256009f7b5e92f` (1 951 824 B), parity 199 native файлов.
- Секция не менялась: `49bd16718ed0dc46f16599255791c7603e8aa2b5f04898784a39d6cacb9d0722` (исправление карты остаётся установленным).
- Owned-проба `gfx266-uniform-census`, 180 с, env `WOL_UNIFORM_CENSUS=1` (`WOL_UNIFORM_MODE cache=0 census=1 ... default=off`).
- Нагрузка: титульный экран/загрузка, 3 781 кадр, `STOP status=TIME_LIMIT` (собственный чистый останов), прогон не покрывает бой.

## Измеренное

- финал: `calls=191838 redundant=87943 skipped=0 uploads=191838 invalidations=1`
- доля повторов: **45,8 %** (87 943 из 191 838)
- один вызов переносит 96 float = 384 B → избыточный трафик ≈ 33,8 MB за 3 781 кадр (≈ 8,9 KB/кадр)
- инвалидаций за прогон: 1 (смена контекста на старте) — ошибок GL в горячем пути не наблюдалось

## Решение

Кэш остаётся **default-off**. Причина: избыточность реальна и измерена, но 8,9 KB/кадр CPU→GPU в пути, который в бою занимает ~44 мс на кадр (replay 27,2 мс, finish 12,9 мс), не даёт основания объявлять выигрыш. Перевод в default требует matched A/B с доказанным равенством пикселей и измеримым эффектом на время кадра; census этого не доказывает. Отдельно зафиксировано: `skipped=0` подтверждает, что сам census ничего не пропускает и на картинку не влияет.

## Файлы

- `runtime.log.xz` + `runtime.sha256` — полный лог прогона (сырой `runtime.log` не коммитится).
- `during-15/45/90.png`, `before-menu.png`, `after-menu.png` — KMS-кадры, включая восстановленное меню Spruce.
- `status-15/45/90.txt` — статус игрового процесса на контрольных точках.
- `handoff.sh`, `effective-env.json`, `harness.log` — точная передача env и работа харнесса.

Завершение: игре отправлен TERM по точному PID, затем KILL только если идентичность сохранилась; MainUI восстановлен (`FINAL_STATE [5519] []`), игровых процессов не осталось. Сейв-танца в этом прогоне нет (титульный экран), поэтому хеши сейвов здесь не приводятся — они проверяются в прогонах с маршрутом.
