# DLC (Reckonin' at Gun Manor) in the IL2CPP port — 2026-10-31

## Symptom

A Steam save made with the add-on refused to load:

> This save was made with add-on content (DLC) that isn't loaded right now. Requires DLC.

The title screen already listed the add-on, so the Steam copy was fine — the game's own gate said no.

## Root cause

Two independent checks, both satisfied by patches now:

1. `com.rlabrecque.steamworks.net.dll` — our stub Steam client returns defaults. The original
   port patched only `GetDLCCount` and `BIsDlcInstalled`, so `BGetDLCDataByIndex` (the call that
   fills the DLC list: app id, availability, name) still reported "nothing installed".
2. `Assembly-CSharp.dll` — `DLC.FHasDlc(string)` is the gate the save loader actually asks. Steam
   fires the `DlcInstalled_t` callback when an add-on is present; the stub never fires it, so the
   game treated the add-on as missing even when the Steam calls answered "installed".

Other Unity ports solve the same problem the same way — they patch the engine-level DLC manager flag
(the game's own flag) instead of trusting Steam. That pattern is what pointed at `DLC.FHasDlc`.

## Fix (`tools/dlcpatch`)

- `GetDLCCount` -> 1
- `BIsDlcInstalled`, `BIsSubscribed`, `BIsSubscribedApp`, `BIsAppInstalled` -> true
- `BGetDLCDataByIndex` -> returns true and fills `pAppID = 930050`, `pbAvailable = true`,
  `pchName = "Reckonin' at Gun Manor"`
- `DLC.FHasDlc(string)` -> true

Patcher log: `steamworks methods patched: 9`, Assembly-CSharp rewritten in the same run.

## Verified on device

- Save `Larry Oakley` (from Steam) loads with no DLC warning.
- In **Dirtwater** the stagecoach offers Gun Manor; travelling there lands on the manor facade
  (screenshot: `evidence/il2cpp-dlc-gunmanor-2026-10-31.png`).
- The add-on is entered from Dirtwater's stagecoach, **not** from Town of Boring Springs.

Metrics while in Dirtwater: `46.5 fps, 21.5 ms avg / 23.5 p99 / 25.5 worst, hitch 0, rss 693 MB`.
The 19.9 fps / 192 ms p99 sample is the scene load.

## Save deployment detail

The port reads saves from `<port>/data/external/`, not `data/files/`. A save copied with its
original timestamp may be ignored or overwritten by the game, so a copy with a fresh ticket
suffix (`save-<name>-<new ticks>.json`) is what actually shows up in the list.
