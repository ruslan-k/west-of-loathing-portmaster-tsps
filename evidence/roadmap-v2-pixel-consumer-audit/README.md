# Пиксельные потребители Sprite — аудит после исправления карты

Владелец подтвердил карту и попросил проверить, где ещё возможны такие же дефекты отображения. Этот аудит отвечает на вопрос по механизму, а не по названиям экранов.

## Механизм (прочитан в реальном коде игры)

`SpriteLoader.TryLoadResourceOrDevCache` получает спрайт по имени через `SprLoad`, затем:

1. сравнивает `|sprite.pixelsPerUnit − ожидаемый PPU| < 1e-4`;
2. при совпадении нормирует `origin` по `texture.width/height` и сравнивает с `sprite.pivot` (допуск 1e-6);
3. при любом расхождении **создаёт замену**: `Sprite.Create(texture, sprite.textureRect, pivot, ожидаемыйPPU, 0, tightMesh)`.

У repack, который уменьшал `m_Rect` и `m_PixelsToUnits` вдвое, ломались оба сравнения, поэтому загрузка по имени возвращала не сериализованный спрайт, а пересобранный: rect в уменьшенных пикселях текстуры при авторском PPU. Дефект карты — частный случай этого механизма.

Потребители, которые реально смешивают авторские пиксельные единицы с размерами rect (тот же класс, что карта):

- `OptionImage.set_sprite` — `LayoutElement.preferredWidth/Height` = **сырые** `Sprite.rect.width/height`;
- `PortraitBuilder.UpdateSize` — `pivot ÷ Sprite.rect.size`, затем `SetSizeWithCurrentAnchors` по `bounds`.

Иммунные (только отношения или нормированные величины — рескейл rect и PPU вместе на них не влияет):

- `OptionsContentBlock.SizeLayoutElement` — отношение `rect.height/rect.width`;
- `WorldOverlay.SetOverlay` — `AspectRatioFitter.aspectRatio = size.x/size.y`;
- `TiledImage.get_preferredWidth/Height` — `(textureRectOffset + textureRect) ÷ pixelsPerUnit`;
- `PortraitBuilder` через `Sprite.bounds` (rect ÷ PPU) и мировые потребители `Element.FInit`, `Waa.CreateGeometry`, `Letterbox.SetEdges`, `Knotty.Start` — мировые спрайты repack не трогает по rect/PPU.

## Кто и с каким PPU вызывает загрузку по имени

Из 39 мест вызова `SpriteForName*`/`TryLoadResourceOrDevCache` (файл `spriteforname-call-sites.tsv`):

- `Map::Start` и `MapScroll::Load` передают **200.0** — единственные два места с UI-PPU; защита карты закрывает их;
- все остальные 28 мест передают **-1.0**, что загрузчик превращает в **3.0** (мировой PPU): инвентарь (`Inventory::SpriteForItem`, `InventorySwitch::LoadFilters`), диалоги (`Dialog::OnCommand`), магазин (`NpcStore::SprIconForItem`), оверлей (`WorldOverlay::SetOverlay`), лоток эффектов, лут (`ClutterSystem::LoadSpriteArray`), персонаж (`PlayerAvatar::ConfigFromActor`, `get_configPlayer`), `Element::FInit`, `Waa::CreateGeometry`.

Следствие: спрайт с авторским PPU 200 при запросе 3.0 не совпадает по PPU, поэтому загрузчик и в исходной игре собирает спрайт заново из `textureRect`. Repack уменьшает `textureRect` вдвое, значит для названных загрузок пиксельный rect уменьшается независимо от того, совпал PPU или нет. Видимый дефект возникает там, где из rect выводится геометрия (карта — исправлено; `OptionImage` и `PortraitBuilder` — потенциально), и не возникает там, где размер задаёт layout (иконки в фиксированных ячейках просто чуть мягче).

## Измеренная экспозиция (core, 4842 спрайта)

- карта: **15 фонов + 42 значка не изменены** — защита из исправления держится;
- **62 спрайта всё ещё с уменьшенными rect+PPU** поверх 11 текстур: иконки инвентаря/журнала/карты/опций, боевой лог (`ui_combatlog2` 1692×1030→846×515), карты победы/поражения (`ui_victorycard`, `ui_defeatcard`), создание персонажа (`cc_*`, `character_creation`), части тела героя (`PC_*`), глифы геймпада (`NX_controller*`), рамки инвентаря;
- 1714 спрайтов изменён только sampling-rect (`textureRect`) при неизменных rect/PPU — это безопасный мирового класса, логический размер сохранён по контракту repack.

Имена этих спрайтов присутствуют в бандле как имена GameObject'ов (531 объект) и не встречаются строковыми константами в `Assembly-CSharp.dll` — присвоение идёт по данным/имени, поэтому вывод «экран заведомо сломан» из статики не следует.

## Цена защиты (измерено, offline)

Восстановление авторских размеров всех 11 текстур при сохранённой обрезке mip-хвостов: **+22,64 MiB** сериализованного payload (крупнейшие: атлас UI Group 0 2048² 6 MiB, `NX_controller` 5,2 MiB, `ui_combatlog2` 5,1 MiB). Это сериализованный объём, а не резидентная RAM.

Решение: расширение защиты **не применяется** этим коммитом. Разумный порядок — сначала доказать живым owned-прогоном, что один из этих экранов действительно проходит через загрузку по имени в raw-pixel потребитель (дешёвая проверка: кадры инвентаря/журнала/опций/создания персонажа против desktop-эталона), и только затем платить 22,6 MiB. Формулировка «дефект» без такого кадра была бы догадкой.
