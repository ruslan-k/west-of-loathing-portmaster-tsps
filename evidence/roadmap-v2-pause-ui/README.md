# Owned-прогон маршрута pause-UI: инъекция ввода проверена, кадров экранов нет

Цель: добраться до экранов, где UI-элементы выводятся из `Sprite.rect` (инвентарь, журнал, опции, создание персонажа), и снять кадры для сравнения с desktop-эталоном. Вопрос аудита: видно ли на этих экранах уменьшение в два раза.

## Что сделано

- Маршрут `route-pause-ui.json` (SHA `0ad5d90c7bab95f8f9d2e4c77653c37c40ea4976faa28ef934f50724a866a0e9`): CONTINUE, затем START; вниз; A; вниз; A; B; B — 7 действий, каждое ≤200 мс удержания, паузы 3–6 с, обратный выход.
- Прогон `pause-ui` через `wol_roadmap_probe.py` с текущим рантаймом `abe18786588646374e608eac9dc02d3cb24af1816c67026fec256009f7b5e92f` и секцией `49bd16718ed0dc46f16599255791c7603e8aa2b5f04898784a39d6cacb9d0722`.
- Все стадии зарегистрированы: `startup, menu, continue-load, game-idle, pause, pause-down1, pause-select, pause-down2, pause-select2, back, back2` — инъекция ввода доходит до игры (после CONTINUE игра стартовала, затем приняла START и навигацию).

## Что не получено

- Кадров по действиям нет: этот `session.py` не делает kmsgrab на каждое действие, а порт не создал каталог captures для метки. В каталоге только `restored-menu.png`.
- Поэтому **визуального ответа по экранам инвентаря/журнала/опций в этом прогоне нет**. Ни один вывод о них из этого прогона не делается.
